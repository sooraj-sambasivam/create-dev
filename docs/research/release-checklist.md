## 7. `/api/import-element`: PASS (with WARN)

Source: `apps/server/src/importElement/route.ts`, `convert.ts`.
- SSRF: PASS. The server never fetches `sourceUrl`, `snapshot.url`, `src` or `href`; the converter "only reads snapshot data". Image `src` must match `^https:\/\/\S+$` and is stored as data for the browser to load; `href` is allow-listed to `#id`, `http(s)`, `mailto`, `tel` (blocks `javascript:`).
- Size: PASS. Route-local `express.json({ limit: "1mb" })`, zod caps (strings 30-2000 chars, children max 300), depth <= 6, nodes <= 300 enforced by `measure`.
- Rate limit: PASS. 30/min per IP, in-memory.
- Path traversal: PASS. Not applicable; saved via `store.save` with generated id.
- WARN: with an `instruction`, each call invokes the paid model (`editNodeWithFallback`); 30/min/IP is permissive for cost.
- WARN: open redirect surface is small: link base comes from `PUBLIC_URL` or the request `Origin`, but non-http origins fall back to localhost. Set `PUBLIC_URL` in production so a spoofed `Origin` cannot choose the returned link host.

## 8. `/api/forms/:appId`: WARN

Source: `apps/server/src/forms/route.ts`, `store.ts`.
- Path traversal: PASS. `isValidAppId` (`^[A-Za-z0-9_-]{1,40}$`) runs in the route and again in `pathFor`; writes go to a temp file and `rename`.
- Size: PASS. 64kb body, fields value <= 4000 chars, key <= 100; store caps 200 submissions per app.
- Rate limit: PASS for POST (30/min/IP). WARN: the GET list route has no limiter.
- Injection: PASS. Mongo query uses a validated string, `{ appId }` only.
- WARN: `GET /api/forms/:appId` is unauthenticated, so anyone who knows or guesses an app id reads every submission (names, emails). App ids are short and may be guessable. Fix before real users: issue an unguessable owner token at app creation and require it on GET (`Authorization: Bearer`), keep POST public. For the demo, state it in the Devpost as demo-grade.
- WARN: there is no unbounded-app limit: any valid `appId` creates a new file under `apps/server/.data/forms` (disk fill). Add a global cap or require a registered app id.
- WARN (speculation): on Vercel the filesystem is read-only except `/tmp`, so the file store likely errors in serverless; set `MONGODB_URI` for any hosted deploy.

## 10. Rate-limit coverage of other expensive routes: FAIL

`createRateLimiter` is applied only in: forms POST, ask, import-element, live, voice token, share create. These routes have no limiter and either call paid vendors or accept large bodies:
- `POST /api/generate` (and edit routes in `generate.ts`), `POST /api/generate-sketch` (10mb), `POST /api/canvas-ops` (10mb), `POST /api/demo` (25mb), `POST /api/transcribe` (ElevenLabs), `POST /api/intent` (Jev/Haiku), `POST /api/upload` (writes to disk, 8 MB each), `/api/image`, `/api/icons/*`.

Risk: anyone who finds the public URL can drain Anthropic, ElevenLabs, TypeSafe and Perceptron credits and fill disk. Remediation (code change, for the owner of those files):

```ts
// in each router file
import { createRateLimiter } from "../middleware/rateLimit";
const limiter = createRateLimiter({ windowMs: 60_000, max: 10 }); // generate/sketch/canvas-ops/demo
router.post("/generate", limiter, ...);
```

Also lower the demo limit from 25mb to what the demo actually needs, and set a spend cap in each vendor dashboard before publishing the URL.

## 11. Rate limiter key behind Vercel proxy: WARN (speculation)

`rateLimit.ts` keys on `req.ip`; `grep "trust proxy"` finds no setting in `apps/server/src`. Express without `trust proxy` reports the proxy socket address, so on Vercel all clients may share one bucket (one user trips the 429 for everyone) or, conversely, buckets are per-instance and reset on cold start. Verify on the deployed URL, then:

```ts
// apps/server/src/app.ts, after const app = express();
app.set("trust proxy", 1);
```

## 12. CORS: PASS (with WARN)

`apps/server/src/app.ts`: allows `http://localhost:*`, `http://127.0.0.1:*`, origins in `ALLOWED_ORIGINS`, and `chrome-extension://*` only when the path starts with `/api/import-element`. No wildcard, no credentials option.
- WARN: any installed extension (any ID) can call `/api/import-element`; acceptable since it is public and rate limited, but pin the ID if you publish the extension: `chrome-extension://<id>`.
- WARN: any localhost port is allowed on a deployed server; harmless without cookies/credentials.
- Set `ALLOWED_ORIGINS=https://<your-domain>` in production, else the deployed web app may rely on same-origin only (works via the Vercel rewrite).

## 13. Extension permissions: PASS (with WARN)

`apps/extension/manifest.json` (MV3): `permissions: ["activeTab","scripting","storage"]`, `host_permissions` only `http://localhost:3001/*` and `http://127.0.0.1:3001/*`. No `<all_urls>`, no `tabs`, no `webRequest`, no `web_accessible_resources`, no `externally_connectable`. Content script is injected on click via `activeTab`, which is the narrowest pattern for "point at any website".
- WARN: `content.js:87` assigns `box.innerHTML` from a static template (no page data interpolated); fine, but keep it static.
- WARN: the options page lets the user set `apiOrigin`/`webOrigin`; a deployed API (https) needs a matching `host_permissions` entry or optional host permission, otherwise the service-worker fetch fails. Add e.g. `"https://<your-domain>/*"` (or `optional_host_permissions`) before the Chrome Web Store build.
- WARN: the snapshot sent to the server is page content from arbitrary sites (may include personal data on the page); show a visible "this sends the selected element to Create" notice in the store listing and privacy policy.
